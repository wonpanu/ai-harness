### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation (`Explore` for code search, `deep-reasoner` for a tangled causal chain) and the fix (`harness-agent`) to subagents. Stay in the lead.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. Reproduce it yourself on the matching surface via the control skill (`run` for CLIs, servers, and Electron apps; `claude-in-chrome` for browser UIs), even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the control skill cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires.
2. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives. Seed them with `how` over the affected subsystem and the **why** skill for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Drive a long or stubborn hunt with Claude Code's `/loop`. Confirm the surviving *mechanism* with runtime evidence before the step-3 architect/interrogate fan-out.
3. Plan the fix. If it crosses a function boundary, `architect` first. Delegate implementation to `harness-agent` (`deep-reasoner` for the hardest changes: cross-cutting design, gnarly concurrency, subtle algorithms). Its brief is the PRD (AGENTS.md "PRD before starting"): the confirmed mechanism, the files in scope, the step 1 repro as the acceptance check, and the test seam. The delegate works through the **tdd** skill, mandatory: first a failing test at that seam that reproduces the defect (red), then the minimal fix (green); refactoring waits for review via **simplifying-code**. The only skip is the tdd skill's own skip clause, written in the todo list as `skip: <reason>`, in which case the step 1 runtime repro is the red. Every reviewer gets the same PRD. A fix you can finish yourself in one turn (one or two file edits) stays with you, per AGENTS.md "When to delegate".
4. Verify on the same surface. The original repro now passes. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
5. Stage the commits so the failing test from step 3 lands before the fix in git history. The test carries `// Arrange`, `// Act`, `// Assert` markers (AGENTS.md "Code style").
   This is the canonical **sequence-verifiable-units** principle skill, the failing test first and the fix on top.
6. Run **Opening a PR** (`playbooks/opening-a-pr.md`).

**Reply** in the harness output style (AGENTS.md "Output style", i-have-adhd). Lead with the root cause and the fix. Then what was broken and how you verified, with the failing-then-passing repro output pasted verbatim. Unslop and technical-writing apply to the PR body and docs, not to this reply.
